# 第五步：对齐月份构成后比较可见签约占比

本步把自然搜索、付费搜索和社交的月内可见签约占比，按同一套月份权重重新汇总。这是描述性比较指标，不是实际签约量增加，也不是最终签约率或因果效果。

## 固定的比较规则

- channels：organic_search, paid_search, social
- common_month_rule：共同首次联系月份：三个指定来源分别都有至少1条线索；不按签约数筛选。
- weight_target：共同月份内三个指定来源合并后的样本月份构成；不代表全企业或全来源。
- weight_formula：该月三个来源合并线索数 / 所有共同月份三个来源合并线索数
- standardization_formula：SUM(同一套月份权重 * 该来源该月记录内可见签约占比)
- date_anomaly_policy：沿用04：日期冲突记录保留在匹配签约与线索计数中，另列标记。
- scope：描述性月份构成调整；不统一随访时长、不解释为因果效果、不进行显著性检验。

共同月份：2017-07至2018-05，共11个月。权重来自这些月份内三个来源合并的5,232条线索。

没有按签约结果筛选月份。某月只有在三个来源分别都有线索时才进入比较；早期月份即使零签约，只要满足分母规则也保留。

原始文件中未纳入共同月份的月份：2017-06（未同时满足三个来源各有线索的规则）。

| social | 1350 | 75 | 5.56% | 5.56% | 5.87% |

原始占比＝该来源可见签约数÷该来源线索数。共同月份占比仍用签约数合计÷线索数合计，不能直接平均月度百分比。此数据中三个来源的全部线索均在共同月份，所以前两种占比相同。

标准化占比＝各月的同一套权重×该来源该月可见签约占比，再把各月贡献相加。标准化后没有新增线索或签约，不能把数值变化当作营销效果提升。

付费搜索减自然搜索：共同月份原始差值+0.4919个百分点；月份构成标准化后差值+0.5215个百分点（展示约+0.52个百分点）。

在本方案下，调整月份构成后这两来源的描述性差异仍然存在。4月的排序与整体不同，不能单凭该月推断整体排序会逆转。本步没有置信区间或显著性检验，不能据此确认渠道优劣。

## 这一步解决和保留的问题

三个来源使用相同的月份构成进行汇总，而不是各自使用自己的月份占比。月份只是一种分层，月内线索特征、日期、销售分配、记录覆盖和跟进情况仍可能不同。

本步没有确认统一数据抽取截止、没有统一随访时长，也没有把最大签约日期当作已知完整观察截止。月份标准化不能补回未被记录的签约。

日期冲突记录按04规则保留，不能据此声称日期问题已修复。不同合理权重定义会对应不同的比较目标；此处不按结果更换主方案。缺少成本与利润，仍不计算ROI或最优预算。

## 学习重点

- WITH：为查询中的中间结果起名，逐层计算。
- HAVING COUNT(*)：在按月份分组后，保留三来源都有线索的月份。
- SUM(...) OVER ()：得到月份合并线索数的总和，用于计算共同权重。
- SUM(月份权重×月内占比)：计算标准化指标；先保留未舍入数，最后再格式化展示。

## 实际执行的SQL

### 05_month_standardization.sql

```sql
-- 第五步：三来源使用相同的首次联系月份权重。
-- 本次方案固定比较自然搜索、付费搜索、社交。
-- 共同月份只按每来源是否有线索确定，不按签约数筛选。
-- 权重目标：共同月份内这三来源合并后的样本月份构成。

WITH selected_channels(channel) AS (
    VALUES ('organic_search'), ('paid_search'), ('social')
),
monthly AS (
    SELECT first_contact_month AS contact_month,
           origin_group AS channel,
           COUNT(*) AS lead_count,
           SUM(has_observed_won) AS won_count,
           SUM(date_order_issue) AS date_issue_count
    FROM lead_overview
    WHERE origin_group IN (SELECT channel FROM selected_channels)
    GROUP BY first_contact_month, origin_group
),
common_months AS (
    SELECT contact_month
    FROM monthly
    GROUP BY contact_month
    HAVING COUNT(*) = (SELECT COUNT(*) FROM selected_channels)
),
pooled_months AS (
    SELECT m.contact_month, SUM(m.lead_count) AS pooled_lead_count
    FROM monthly AS m
    JOIN common_months AS c ON m.contact_month = c.contact_month
    GROUP BY m.contact_month
),
weights AS (
    SELECT contact_month,
           pooled_lead_count,
           1.0 * pooled_lead_count / SUM(pooled_lead_count) OVER () AS month_weight
    FROM pooled_months
),
all_counts AS (
    SELECT channel, SUM(lead_count) AS all_lead_count, SUM(won_count) AS all_won_count
    FROM monthly
    GROUP BY channel
),
common_results AS (
    SELECT m.channel,
           SUM(m.lead_count) AS common_lead_count,
           SUM(m.won_count) AS common_won_count,
           SUM(w.month_weight * 100.0 * m.won_count / m.lead_count) AS standardized_won_pct,
           COUNT(*) AS common_month_count,
           SUM(m.date_issue_count) AS common_date_issue_count
    FROM monthly AS m
    JOIN weights AS w ON m.contact_month = w.contact_month
    GROUP BY m.channel
)
SELECT a.channel,
       a.all_lead_count,
       a.all_won_count,
       100.0 * a.all_won_count / a.all_lead_count AS all_observed_won_pct,
       c.common_lead_count,
       c.common_won_count,
       100.0 * c.common_won_count / c.common_lead_count AS common_observed_won_pct,
       c.standardized_won_pct,
       c.common_month_count,
       (SELECT SUM(pooled_lead_count) FROM pooled_months) AS shared_weight_lead_count,
       c.common_date_issue_count
FROM all_counts AS a
JOIN common_results AS c ON a.channel = c.channel
ORDER BY a.channel;
```

### 05_month_weights.sql

```sql
-- 月份权重及各来源的月内占比；保留未舍入数参与加权。
-- 同一个月份的month_weight，对三来源完全相同。
-- weighted_contribution_pp是该月对最终标准化占比的贡献，单位为百分点。

WITH selected_channels(channel) AS (
    VALUES ('organic_search'), ('paid_search'), ('social')
),
monthly AS (
    SELECT first_contact_month AS contact_month,
           origin_group AS channel,
           COUNT(*) AS lead_count,
           SUM(has_observed_won) AS won_count,
           SUM(date_order_issue) AS date_issue_count
    FROM lead_overview
    WHERE origin_group IN (SELECT channel FROM selected_channels)
    GROUP BY first_contact_month, origin_group
),
common_months AS (
    SELECT contact_month
    FROM monthly
    GROUP BY contact_month
    HAVING COUNT(*) = (SELECT COUNT(*) FROM selected_channels)
),
pooled_months AS (
    SELECT m.contact_month, SUM(m.lead_count) AS pooled_lead_count
    FROM monthly AS m
    JOIN common_months AS c ON m.contact_month = c.contact_month
    GROUP BY m.contact_month
),
weights AS (
    SELECT contact_month,
           pooled_lead_count,
           1.0 * pooled_lead_count / SUM(pooled_lead_count) OVER () AS month_weight
    FROM pooled_months
)
SELECT m.contact_month,
       m.channel,
       m.lead_count,
       m.won_count AS observed_won_count,
       100.0 * m.won_count / m.lead_count AS observed_won_pct,
       w.pooled_lead_count,
       w.month_weight,
       w.month_weight * 100.0 * m.won_count / m.lead_count AS weighted_contribution_pp,
       m.date_issue_count
FROM monthly AS m
JOIN weights AS w ON m.contact_month = w.contact_month
ORDER BY m.contact_month, m.channel;
```
