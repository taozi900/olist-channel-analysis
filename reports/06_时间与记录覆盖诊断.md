- 有177条签约的日历日期晚于样本最后首次联系日期。不能把线索采样末日当成签约记录的截止。

首个可见签约晚于最早首次联系，只能说明文件中事件时间覆盖不同，不能直接证明早期记录被漏掉。最大签约时间也只是最后可见事件，不是已证实的统一随访截止；未匹配者不自动成为失单或已知右删失。

## 时长定义与异常处理

日历时长＝签约日期减首次联系日期。先去掉时分秒再相减；0天表示同日，不表示零小时。首次联系没有时间信息，因此不报告精确小时耗时。

全部842条匹配签约记录中，有效日历时长841条、负时长1条、无法解析日期0条。
负时长与无法解析记录仅在本步时长分布中单列，不删原始记录；04／05的匹配签约计数不变。未观察签约的线索没有可用签约时长，不填0天。

## 实际执行SQL

### 06_date_coverage.sql

```sql
-- 日期范围只表示文件内记录覆盖，不代表已知完整随访截止。
-- 所有可见签约均纳入覆盖检查，包括日期冲突记录。

SELECT
    COUNT(*) AS lead_count,
    SUM(has_observed_won) AS observed_won_count,
    SUM(1 - has_observed_won) AS unmatched_won_count,
    MIN(first_contact_date) AS first_contact_min,
    MAX(first_contact_date) AS first_contact_max,
    MIN(won_date) AS won_min,
    MAX(won_date) AS won_max,
    SUM(date_order_issue) AS date_issue_count,
    SUM(CASE
        WHEN DATE(won_date) > (SELECT MAX(first_contact_date) FROM mql)
        THEN 1 ELSE 0
    END) AS won_after_last_contact_date_count
FROM lead_overview;
```

### 06_won_months.sql

```sql
-- 这次按“签约发生月份”统计，含日期冲突原记录。
-- 与04按“首次联系月份”分组的指标，含义不同。

SELECT
    SUBSTR(won_date, 1, 7) AS won_month,
    COUNT(*) AS observed_won_count
FROM lead_overview
WHERE has_observed_won = 1
GROUP BY SUBSTR(won_date, 1, 7)
ORDER BY won_month ASC;
```

### 06_won_calendar_days.sql

```sql
-- 仅获取文件内匹配到签约的线索，不给未签约者补0天。
-- DATE去掉时分秒；差值是日历天数，不是精确24小时耗时。
-- 原记录全部保留，负值或无法解析日期的记录单独标记。

SELECT
    mql_id,
    origin_group AS channel,
    first_contact_date,
    won_date,
    CAST(JULIANDAY(DATE(won_date)) - JULIANDAY(DATE(first_contact_date)) AS INTEGER) AS calendar_days_to_won,
    CASE
        WHEN DATE(won_date) IS NULL OR DATE(first_contact_date) IS NULL THEN 'invalid_date'
        WHEN DATE(won_date) < DATE(first_contact_date) THEN 'negative_interval'
        ELSE 'valid_duration'
    END AS duration_status
FROM lead_overview
WHERE has_observed_won = 1
ORDER BY mql_id;
```
